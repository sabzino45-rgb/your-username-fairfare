# Cycle 1 privacy and compliance review

_Privacy/Compliance agent, 2026-11-20. This is advice, not legal clearance. Nothing here is a legal opinion. Lawful basis, Uber's terms and the DPIA decision belong to the owner and a solicitor (see human_gates.md)._

## Verdict in one paragraph

This cycle's new flow is sound. Screenshots from the share target, paste and drop are read on the phone. The image never leaves the device, and the share hand-off cache is deleted after it is read. No raw OCR text is saved. eval_set/ holds only synthetic text.

**One blocking finding, from before this cycle:** every page load sends the driver's IP address, user agent and the fact that they use FairFare to Google Fonts (fonts.googleapis.com and fonts.gstatic.com, US). The app works without it. My role says I block on any personal data sent without need, so this cycle is BLOCK. The fix is small and listed below.

**To unblock:** remove the three Google Fonts `<link>` tags from app/index.html. Either self-host the font files under app/ (and add them to SHELL in sw.js) or use system fonts. Then confirm in a browser network log that the page makes no request to fonts.googleapis.com or fonts.gstatic.com. Nothing else is required to pass. The other items below are recommendations or human gates.

## eval_set/ redaction check

- 80 cases (60 in synthetic.jsonl, 20 in synthetic_fullscreen.jsonl). **Every case has `"origin": "synthetic"`. There are no pilot cases, no images, no base64 and no image paths.** No case has keys beyond id/origin/kind/note/ocr_text/expected_fields/profile.
- Output of `redact()` on each `ocr_text`:
  - synthetic.jsonl: 32 "diffs", all the same thing: a trailing newline dropped by `splitlines`/`join`. **No content redacted.**
  - synthetic_fullscreen.jsonl: 4 diffs, all false positives. In syn-fs-004, -014 and -015, `Trip Radar` became `[NAME]`. In syn-fs-005, `Turn left onto Station Road` became `Turn left onto[ADDRESS]`, a made-up street with no house number.
  - **Missed by redact.py (false negatives):** `Messages · Alex: that's £15 for the tickets` (syn-fs-008), `WhatsApp · Sam: owe you £20 for petrol` (syn-fs-019), `Calendar · Dentist in 15 min` (syn-fs-016). These are **invented** names in synthetic cases, so this is **not unredacted personal data and not a block**. But this is exactly what real full-screen screenshots will contain: third parties' names and message text, sometimes health-related. **redact.py would let them into eval_set/** (R5).
- Parser output: `Offer` holds only numbers, surge, rating, source and warnings. The docstring says it never returns or stores raw text. `run_eval.py --verbose` prints id, decision, confidence and missing fields, never `ocr_text`. reports/cycle-1/eval.json and reports/eval_baseline.json contain no `ocr_text`.

## Recommendations (not blocking unless stated)

- **R0 (required to unblock):** remove Google Fonts from app/index.html. Self-host or use system fonts. Verify with a network log.
- **R1:** self-host Tesseract.js (`tesseract.min.js`, `worker.min.js`, the core WASM files and `eng.traineddata`) under app/ and set `workerPath`, `corePath` and `langPath`. This removes the third party, the transfer and the supply-chain risk, and lets OCR work offline. Size cost is roughly 5-15 MB. If you keep the CDN, add `integrity` and `crossorigin` to the script tag. That only covers the first file, because the worker, core and language data load separately.
- **R2:** add a `<meta http-equiv="Content-Security-Policy">` that limits `script-src`, `connect-src`, `worker-src` and `font-src` to 'self' (plus jsDelivr if R1 isn't done). Also add a short in-app privacy notice: what is stored on the phone, that nothing is uploaded, which outside hosts are contacted and why, and how to delete everything. The same text can back up Growth's message.
- **R3:** add a "Delete all my FairFare data" control (localStorage `ff.*`, the Cache Storage entries, Tesseract's IndexedDB). Consider an automatic retention limit on history and feedback (e.g. 12 months), and actually removing notices after 3 h rather than only hiding them.
- **R4:** delete the share hand-off from both ends. Before writing a new share, sw.js could also drop any entry older than a few minutes (it already deletes the older copy). Or the SW could pass the Blob straight to the client with `postMessage` and never touch disk. Low priority.
- **R5 (required before any pilot case enters eval_set/):** extend tools/redact.py to cover notification previews (`App · Name: text` and `Name: text` on the same line). Replace the whole preview line. A full-screen offer only needs the card. Add the 3 missed patterns above as tests, and fix the `Trip Radar` false positive (add it to KEEP_WORDS). A human must still check every case, as the README says.
- **R6:** pilot screenshot text in eval_set/ needs the driver's informed agreement. Keep only the redacted text, never the image. Write down where the original image is deleted (the driver's phone, any chat it was sent through).
- **R7 (Growth contact data):** collect as little as possible (first name plus one contact route). Keep it in one place, not in the repo. Name initials only in `research/`. Agree a deletion date (e.g. contact details deleted within 30 days after the pilot ends, unless the driver opts in to stay in touch). Add a one-line privacy statement to the recruitment message, e.g. "If you message me, I'll keep your name and number only to arrange the check-in, and delete them when the pilot ends." The draft's "your data stays on your phone" should become "the app keeps your data on your phone" so it doesn't seem to cover contact details. Don't ask drivers to send screenshots of Uber screens or of their Owner view by WhatsApp. Ask them to read the numbers out. Check whether the owner must pay the ICO data protection fee.
